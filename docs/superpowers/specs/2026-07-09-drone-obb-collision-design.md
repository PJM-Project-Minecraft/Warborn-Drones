# Полномодельная коллизия дронов (OBB) — Lancet и Shahed-136

Дата: 2026-07-09. Статус: одобрено пользователем.

## Цель

Хитбокс самолётных дронов (ZALA Lancet, Shahed-136) должен покрывать всю модель —
фюзеляж, крылья, хвост — а не только маленький центральный AABB:

1. **Попадания**: пули, снаряды и взрывы должны попадать по крыльям и фюзеляжу
   при любом крене/тангаже.
2. **Столкновения с блоками**: если крыло задело стену/дерево — дрон детонирует
   (сейчас Ланцет проверяет только центральный AABB и raycast носа).

FPV и Mavic не трогаем — их AABB почти совпадает с моделью.

## Решение

Используем готовую OBB-систему форка SuperbWarfare-fork-PJM (повёрнутые боксы,
data-driven). `DroneEntity → GeoVehicleEntity → VehicleEntity implements OBBEntity`:
при непустом списке OBB в vehicle-data SBW сам:

- каждый тик обновляет позицию/поворот боксов по yaw/pitch/roll сущности
  (`VehicleEntity.updateOBB`, transform "Default" → `VectorTool.combineRotations`;
  крен Ланцета уже пишется через `setZRot` в стандартное поле `roll` — подхватится);
- перехватывает попадания снарядов (`ProjectileUtilMixin`, поиск кандидатов
  с `inflate(8)` — крылья покрыты);
- включает дрона в `Level.getEntities` по OBB (`LevelMixin`) — взрывы/AoE находят;
- рисует зелёную отладку боксов по F3+B (`EntityRenderDispatcherMixin`).

### 1. Перенос vehicle-data в путь форка

Форк загружает vehicle-data через `FileToIdConverter.json("sbw/vehicles")`:
id = `<namespace>:<путь файла>`. Существующие файлы аддона в
`data/superbwarfare/vehicles/wrbdrones/*.json` **мёртвые** (наследие старого
апстрима) — форк их не читает.

- Перенести 4 файла в `data/wrbdrones/sbw/vehicles/`:
  `fpv_drone.json`, `mavic_drone_no_drop.json`, `mavic_drone_with_drop.json`,
  `zala_lancet.json`. Ключ `"ID"` внутри файла больше не нужен (id из пути).
- Создать `data/wrbdrones/sbw/vehicles/shahed136.json`.

### 2. Секции "OBB" в JSON

Формат SBW (`OBBInfo`): `Size` = полуразмеры в блоках, `Position` = смещение
от центра сущности, опционально `Part`. Статического поворота отдельного бокса
нет (поле `Rotation` — только ключ трансформа), поэтому наклонные плоскости
аппроксимируются несколькими AABB-сегментами в локальных осях.

Оси: координаты OBB зеркальны geo-модели — `OBB = (−geoX, geoY, −geoZ)`
(выверено по A-10 форка: хвост geo z≈+5 ↔ OBB z≈−5). У обеих наших моделей
нос в geo на −Z ⇒ в OBB-координатах нос на +Z.

**Lancet** (geo: размах ±0.95, длина 2.75, X-образные крылья двумя парами):
- фюзеляж: ~Size [0.16, 0.16, 1.38], Position [0.04, 0.54, −0.07];
- передняя X-пара (geo z −0.75…−0.44 → OBB z ≈ +0.6): 2–3 плоских сегмента
  «лесенкой» по высоте (крылья наклонены ±40°);
- задняя X-пара (OBB z ≈ −0.65): аналогично;
- хвост/пропеллер: небольшой бокс на OBB z ≈ −1.4.

**Shahed-136** (geo: размах ±1.56, длина 3.7, дельта-крыло):
- фюзеляж: ~Size [0.12, 0.13, 1.63], Position [0, 0.13, +0.44];
- консоли крыла L/R: по ~Size [0.72, 0.06, 1.13] на x ≈ ±0.81;
- концевые шайбы: ~Size [0.03, 0.25, 0.31] на x ≈ ±1.53, z ≈ −1.13;
- хвостовой блок: ~Size [0.34, 0.10, 0.22], z ≈ −1.4.

Числа предварительные — финальная подгонка в `runClient` по F3+B.

### 3. OBB против блоков (детонация крылом)

SBW OBB-система блоки **не** проверяет — только сущности/снаряды. Добавляем:

- `util/ObbBlockCollision` — dist-нейтральный утиль: для каждого OBB дрона
  строим AABB-обёртку по 8 вершинам (`OBB.getVertices()`), берём
  `level.getBlockCollisions(entity, envelope)` и проверяем каждый AABB формы
  через `OBB.isColliding(obb, blockAabb)`.
- `ZalaLancetEntity`: в серверном полётном тике после `SAFE_LAUNCH_TICKS`
  при пересечении → `explode()`. Предиктивный `willHitBlock` (raycast по
  motion) остаётся — он ловит пролёт сквозь тонкие преграды на скорости.
- `Shahed136Entity`: та же проверка при `isLaunched()`.
- Только сервер, раз в тик. Порядок: проверка после `super.tick()`
  (OBB уже обновлены `updateOBB`).

### 4. Что не меняется

- Ванильный `.sized(...)` AABB остаётся (трекинг, подбор, сетевой спавн).
- Формула сигнала, HUD, полётная модель — не затрагиваются.
- FPV/Mavic получают только перенос JSON (без OBB — поведение прежнее).

## Риски / проверки

- С непустым OBB у `VehicleEntity` включаются `handlePartDamaged` /
  `handlePartHealth` — для боксов с дефолтным `Part: Body` побочных эффектов
  быть не должно; проверить при тесте, что урон по дрону работает как раньше.
- Проверить, что перенесённые EngineSound-конфиги не меняют звук (дроны и так
  глушат SBW-звук через `getEngineSoundVolume()=0`).
- Тест: runClient — F3+B рамки по модели; выстрелы по крылу засчитываются;
  крыло о стену → взрыв; обычный полёт/посадка без ложных детонаций.
